# LET ME CHECK? V2 · v3.14.2 本机 FFmpeg 逐帧输出

## 版本与范围

本包以 v3.14.1 DeepSeek 联合修改版为渲染基线，升级为 v3.14.2 方案 B。保留 98 个镜头、1920×1080 画布、30fps、双语字幕、现有镜头边界与素材；本轮仅修复片尾输出帧数，并为 S003、S017 后半的高清裁切画面增加轻微呼吸运动。未改 \`cg01Montage\`、图层顺序、字幕、时间轴、\`transitionIn\`、镜头参数或 S079。

## 使用

1. 解压整个执行包。
2. 确认电脑已安装 Python 3 和 FFmpeg。若 FFmpeg 不在 PATH 中，可在页面内填写 \`ffmpeg.exe\` 完整路径。
3. 双击 \`启动本地导出.bat\`。启动器会在 \`127.0.0.1\` 上启动本地服务并打开 \`index.html\`。不要直接双击 HTML 来执行导出；浏览器的 \`file://\` 安全限制不允许页面直接调用本机程序。
4. 在页面载入本地 WAV 母带。
5. 选择 CRF（默认 18）与音频编码（AAC 320 kbps 或 ALAC），点击“逐帧渲染并导出 MP4”。
6. 导出完成后，到执行包目录下的 \`exports\` 文件夹查看 MP4。

## 输出方式与规格

Canvas 按绝对时间逐帧渲染 1920×1080 画面，30fps，共 8246 帧，目标视频时长为 274.866667 秒。每 4 帧组成一个小批次，经本机 loopback HTTP 服务直接写入 FFmpeg 的 \`image2pipe\` 输入；FFmpeg 同时读取本地母带 WAV，编码 H.264 并封装音频。音频链使用 \`-af apad\` 补足音频，并用 \`-t 274.866667\` 固定输出时长，确保 MP4 容器时长与 8246 帧规格一致；未使用 \`-shortest\`，避免音频包缓冲令容器时长超出目标。不会实时录制，不使用 MediaRecorder，不下载 FFmpeg WebAssembly，也不把素材或音源上传到远端服务。

## 本轮修改

- 新增 \`v314CropBreathe()\`，供 S003 与 S017 后半使用：以原图裁切为基础，加入 2% 慢推、0.3% 横移、0.2% 纵移和 2% 柔光呼吸。
- FFmpeg 输出命令加入 \`-af apad\`，与 \`-shortest\` 配合补齐尾部静音并保留完整 8246 帧。
- 独立 \`index.html\` 可用于检查页面；要使用本机 FFmpeg 导出，必须通过配套 \`.bat\` 启动本地服务。

## 说明

- WAV/音源由用户本地加载，不上传、不内嵌；本项目不公开音乐、母带或最终有声成片。
- 取消按钮会终止本地 FFmpeg 任务，并恢复预览时间和控件状态。
- 代码语法与包完整性检查通过，不等于已经渲染验收整片 8246 帧。完整输出后仍应按单独修改记录中的验收表检查帧数、时长、解码与 S003/S017 帧差。
