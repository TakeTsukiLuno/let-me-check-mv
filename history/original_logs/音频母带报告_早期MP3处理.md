## 一句话结论

这是一首 **Suno AI 生成的 48kHz / 184kbps MP3**，真正的问题不是"糊"，而是**调音偏暗、低频偏重、3–8kHz 存在感塌陷、整体响度偏小且真峰值已超标**。
我按"不改编曲、只做母带级修复"的原则重制了两版：**A 平衡自然（-14 LUFS）** 与 **B 更响更厚（-11.5 LUFS）**，并交付无损 + 兼容格式。独立 QA 复核 **PASS（6/6 项）**。

## 一、源文件诊断

| 项目 | 实测值 | 判断 |
|---|---|---|
| 格式 | MP3 48kHz 立体声，183.6kbps，4分34.8秒 | 有损二次转码（原始为 AAC/isom 容器） |
| 元数据 | AIGC: sunoai `generate-100161437-…` | Suno 生成曲 |
| 有效带宽 | 19.2kHz 处硬切（-69.9 → -122.9 dBFS，跌 53dB） | 有损压缩砖墙，更高频段无内容 |
| 整体响度 | **-15.28 LUFS** | 比流媒体标准 -14 小 1.3dB |
| 真峰值 TP | **+0.13 dBTP** | 已超 0dBTP，解码时存在削顶 |
| 动态范围 LRA | 9.10 LU | 正常 |
| 频谱重心 | 1046 Hz | **偏暗**（现代流行通常 1.5–2.5kHz） |
| 频段失衡 | 630–1k 比相邻高约 2dB（闷/盒音）；2.5k–8k 比低频低 5–10dB（缺存在感） | 典型"暗、闷、远景感" |
| 立体声 | L/R 相关 0.80，Side/Mid -9.5dB | 偏窄，低频控制尚可 |
| 底噪 / DC | -79.8dBFS / 8e-6 | 干净，不需要降噪 |

**结论：不需要"修复失真"，需要重做平衡（EQ）+ 动态整理 + 响度标准化。**

## 六、复现口径

- 响度/真峰/LRA：`ffmpeg -i <file> -af loudnorm=I=-14:TP=-1:LRA=11:print_format=json -f null NUL`
- 采样峰：`ffmpeg -i <file> -af volumedetect -f null NUL`
- 削波/DC/单声道/LTAS/短时 RMS：`audio_work/qa_full.py`（numpy float64 解析，|x|>0.999 判削波，100ms 窗 RMS，Welch 1/3 oct）
- 频谱图：`ffmpeg -ss 228 -t 30 -i <file> -lavfi showspectrumpic=s=1600x900:mode=combined:scale=log:legend=1`

## 七、边界与可选调整

1. **有损音源的物理天花板**：19.2kHz 以上没有内容，任何处理都无法还原；本方案没有用插值/生成式手段伪造高频（那会产生金属味），只在有内容的频段做平衡。
2. **没有再降噪**：底噪仅 -79.8dBFS，降噪收益为零、风险很高（会吃掉气声和混响尾音）。
3. **两版怎么选**：耳机细听 / 上传流媒体 → **A**；手机外放 / 车载 / 短视频，需要"一开口就响" → **B**（动态比 A 少约 2.6dB）。
4. **还能怎么调**：若想更亮 / 更暖 / 更宽，可按 0.5dB 步进在这条链上再出定制版，不会伤原始细节。
